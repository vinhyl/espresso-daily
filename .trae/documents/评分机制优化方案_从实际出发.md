# 评分机制优化方案（从实际出发）

> 上一轮方案见 [评分机制按内容类型差异化重构.md](file:///Users/vvvvvv/Documents/ai projects/espresso-daily/.trae/documents/评分机制按内容类型差异化重构.md)（6 类型 × 6 维度，已落地代码但 to_markdown 改动未完成，实际产出仍是旧六维）。本方案是**替代**而非续作——从 44 条真实数据出发，承认上一轮维度集设计本身就有问题（维度太多、定义太学术、relevance 无否决权），需要结构性改革。

---

## 一、日报网站定位（评分的锚点）

**定位**：意式浓缩咖啡垂直日报，每日聚合 5-15 条高价值意式资讯。
**受众**：意式爱好者（新手到进阶），核心关心萃取操作、器具选购、调参排障。
**评分的两个职责**：
1. **内部筛选**：挡掉无关/低质内容（min_score=60 门槛）
2. **用户预览**：分数 badge 帮读者快速判断"值不值得读"

**推论**：评分必须先保证"进入评分池的都是意式相关内容"，否则评分再精细也无效——非意式内容拿 82 分最高，说明评分系统已失信。

## 二、真实数据暴露的问题（44 条已发布内容）

### 问题 1：初筛失效，无关内容进入日报并拿高分

| 内容 | 分数 | 本应 |
|---|---|---|
| 哥伦比亚荫栽咖啡与鸟类多样性 | **82（全场最高）** | 初筛拒（种植/生态） |
| Excelsa 咖啡豆与气候变化 | 78 | 初筛拒（品种/农业） |
| Moft 咖啡渣笔记本保护套 | 62 | 初筛拒（周边商品，命中 PRESCREEN_REJECT） |
| 每天五杯咖啡无碍健康 | 62 | 初筛拒（健康研究，命中 PRESCREEN_REJECT） |
| "first machine" 展示帖 | 75 | 初筛拒（纯展示，命中 PRESCREEN_REJECT） |

**根因**：LLM 初筛放行太宽；走 LLM 时 `PRESCREEN_REJECT_PATTERNS` 被绕过（那套词表只在规则回退 `_rule_prescreen` 里检查）。

### 问题 2：relevance 无"一票否决"权，凑分就能过线

鸟类研究 relevance 应接近 0，但其他维度（novelty/evidence）给了高分，总分 82。
**根因**：relevance 只是六维之一（满分 25-30），即使打 0，其他维度凑分也能过 60。这就是"凑分过线"——维度越多，凑分空间越大。

### 问题 3：优质意式内容反被压低

| 内容 | 分数 | 对比 |
|---|---|---|
| 冷冻豆解决涩感（DF54+Bambino+参数+方案） | **62** | 和咖啡渣笔记本同分 |
| Timemore 078s 磁编码器改装（硬件 mod） | 78 | 合理 |
| 意式用水指南（TWW/硫酸镁/碱度参数） | 78 | 合理 |

**根因**：对 community_case 评 evidence（社区个案天生低证据），维度不适配拖低总分；LLM 对"单人经验"整体压低。

### 问题 4：分数集中，无区分度

72 分 14 条、62 分 11 条、78 分 8 条——双峰/三峰。
**根因**：
- LLM 中庸倾向（每维给 60-75% 满分）
- 规则回退"中性基线"（满分 50%）+ 关键词加成 → 天然落在 60-75
- 5-6 维 × 每维 15-25 分 → 单维差异 2-3 分被平均化

### 问题 5：维度定义脱离"材料可见信号"

LLM 只有 RSS 摘要或抓取全文前 9000 字，却要评"学术严谨度""方法严谨度"——这些需要看全文方法论才能判断，LLM 只能猜，必然中庸打分。

## 三、优化方案（5 个改革）

### 改革 1：初筛与评分分工——初筛守"意式相关性"硬门

**原则**：初筛的唯一职责是"这条该不该进入评分池"，不评价值。评分阶段不再重复做"意式相关性"判断。

**强化措施**：
1. `PRESCREEN_REJECT_PATTERNS` 在 LLM 初筛路径也要**强制程序化检查**（不依赖 LLM 自觉）——LLM 返回前先过一遍词表，命中即拒，覆盖 LLM 的放行
2. 初筛 LLM prompt 收紧"硬拒清单"：种植/产地/农业/供应链/健康研究/周边商品/纯展示/选购咨询，命中即 accept=false
3. 初筛返回 `espresso_core=false` 的条目：除非 `content_type=research` 且研究主体是 espresso/moka pot，否则直接拒

**预期效果**：鸟类研究、Excelsa 豆、咖啡渣笔记本、健康研究、展示帖全部在初筛被拦，不进入评分。

### 改革 2：relevance 做"一票否决"，不参与总分

**机制**：
- relevance 仍保留为每类型的维度之一（参与 frontmatter 落盘/质量报告），但额外加一道**否决门槛**
- `relevance < 满分 × 50%` → 直接判死（Judgment.score = 0 或标记 reject），不进入 min_score 比较
- 其余维度照常评分，总分 = 各维之和（含 relevance）

**效果**：即使初筛漏放一条无关内容，relevance 否决权也能兜底——鸟类研究 relevance 打 5/25（< 12.5），直接拒，无论其他维度多高。

**为什么是 50% 而不是更高**：留出"意式占一部分"的合理空间（如一篇同时讲意式和手冲的评测，relevance 可能打 12/25=48%，仍可能误杀）。50% 是"通篇围绕意式"与"意式占一部分"的分界线。

### 改革 3：每种类型 3-4 维（不是 5-6 维），每维满分 25-40

**原则**：
1. **只评"材料可见信号"**：数据/参数/结论/步骤/规格——这些在 RSS 摘要或全文里能看到。不评"学术抽象"（严谨度/方法论）——LLM 看不到方法论，只能猜
2. **每维满分 ≥ 25**：让 LLM 敢拉开差距（0-10 vs 25-35 差 25 分，远比 5 vs 8 差 3 分明显）
3. **维度数 ≤ 4**（含 relevance）：减少凑分空间，增大单维区分度
4. **总分仍 = 各维之和 = 100**，min_score=60 语义不变

**为什么减维度**：上一轮 5-6 维的设计让 LLM 在每个小维度上都给"中性分"，叠加后所有内容都落在 65-75。减到 3-4 维后，单维差异对总分影响更大，区分度自然提升。

### 改革 4：各 content_type 维度集（从"读者价值"出发）

#### expert_experiment（专家实验/建模 · Barista Hustle / Coffee Ad Astra）
读者价值：**学到可操作的原理或结论**

| 维度 | 满分 | 评什么（材料可见信号） |
|---|---|---|
| relevance | 25 | <12 直接拒 |
| 结论价值 | 35 | 有明确结论/修正共识/反常识=30-35；有数据但结论模糊=15-29；无结论=0-10 |
| 数据具体度 | 25 | 有测量数据+参数+对比=22-25；部分数据=12-21；纯定性=0-10 |
| 可操作性 | 15 | 读者能照做/调参=13-15；有方向需自行试=7-12；纯理论无操作=0-6 |
| 合计 | 100 | |

**对比旧设计**：去掉 methodology（LLM 看不到实验设计）、reproducibility（和可操作性重复）、evergreen（太抽象）。结论价值升到 35 分——专家实验的核心价值就是"得出了什么结论"。

#### independent_review（独立评测 · CoffeeGeek）
读者价值：**选购/调参指导**

| 维度 | 满分 | 评什么 |
|---|---|---|
| relevance | 25 | <12 直接拒 |
| 测试覆盖 | 35 | 多机型/多参数/多场景对比=30-35；中等覆盖=15-29；单点测试=0-10 |
| 数据深度 | 25 | 完整实测数据+对比表=22-25；部分数据=12-21；主观印象=0-10 |
| 选购指导 | 15 | 明确购买建议=13-15；有方向=7-12；无建议=0-6 |
| 合计 | 100 | |

**对比旧设计**：去掉 independence（评测独立性是前提，不是评分维度——不独立的归 news）、evergreen。测试覆盖升到 35——评测的核心价值就是"测了多少"。

#### news（行业消息 · Sprudge / PDG / DCN）
读者价值：**知道意式行业发生了什么**

| 维度 | 满分 | 评什么 |
|---|---|---|
| relevance | 25 | <12 直接拒 |
| 信息密度 | 35 | 实质信息丰富（时间/数据/人物/结论）=30-35；中等=15-29；营销话术/复述=0-10 |
| 行业影响 | 25 | 影响意式用户/品牌/供应链=22-25；行业内部=12-21；边缘动态=0-10 |
| 时效性 | 15 | 当天/本周=13-15；本月=7-12；旧闻=0-6 |
| 合计 | 100 | |

**对比旧设计**：去掉 source_credibility（来源身份在初筛已判断，不重复评分）、impact 合并进行业影响。信息密度升到 35——新闻的核心价值就是"有多少实质信息"。

#### community_case（社区个案 · Reddit r/espresso）
读者价值：**可复用的调参/排障经验**

| 维度 | 满分 | 评什么 |
|---|---|---|
| relevance | 25 | <12 直接拒 |
| 参数具体度 | 35 | 机型+参数+已尝试步骤完整=30-35；部分=15-29；只有描述=0-10 |
| 解决方案 | 25 | 有明确解决路径=22-25；有方向无定论=12-21；纯求助=0-10 |
| 可复现性 | 15 | 他人可照做排查=13-15；部分可复现=7-12；信息缺失=0-6 |
| 合计 | 100 | |

**对比旧设计**：去掉 discussion（评论区价值不稳定，且 RSS 抓不到完整评论）、evergreen。参数具体度升到 35——社区个案的核心价值就是"信息有多具体"。

**预期效果**：冷冻豆解决涩感（有机型+参数+方案+可复现）→ 参数具体度 30 + 解决方案 22 + 可复现性 13 + relevance 22 = 87 分。远高于咖啡渣笔记本（会被初筛拒）。

#### announcement（官方公告 · 新品/规格/固件/召回）
读者价值：**选购决策参考**

| 维度 | 满分 | 评什么 |
|---|---|---|
| relevance | 25 | <12 直接拒 |
| 规格完整度 | 40 | 参数/特性/价格给齐=35-40；部分规格=18-34；只有名字=0-15 |
| 决策影响 | 25 | 直接影响读者选购/升级=22-25；间接参考=12-21；与读者无关=0-10 |
| 时效性 | 10 | 首发/独家=9-10；同步报道=5-8；旧信息=0-4 |
| 合计 | 100 | |

**对比旧设计**：去掉 impact（和决策影响重复）、novelty（和时效性重复）。规格完整度升到 40——公告的核心价值就是"规格说清楚了没"。

#### research（学术研究 · OpenAlex / Crossref）
读者价值：**对意式操作有指导的研究结论**

| 维度 | 满分 | 评什么 |
|---|---|---|
| relevance | 25 | <12 直接拒 |
| 结论可操作性 | 40 | 直接指导意式操作=35-40；间接启发=18-34；纯理论无指导=0-15 |
| 证据可见度 | 25 | 有数据/样本/统计=22-25；有方法描述=12-21；只有结论=0-10 |
| 新颖性 | 10 | 首次/修正共识=9-10；增量研究=5-8；复述已知=0-4 |
| 合计 | 100 | |

**对比旧设计**：去掉 rigor（LLM 看不到同行评审状态）、evidence（改为"证据可见度"——评材料里有没有数据，而不是学术证据等级）、applicability（合并进结论可操作性）、evergreen。结论可操作性升到 40——研究对日报读者的价值就是"能不能指导操作"。

**预期效果**：泛咖啡健康研究（研究主体非意式）→ relevance 打 5/25 → 否决拒。意式萃取率研究（有数据+能指导操作）→ relevance 22 + 可操作性 35 + 证据 22 + 新颖性 8 = 87。

### 改革 5：对抗 LLM 中庸倾向

**问题**：当前 prompt 写了"多数条目应落在 55-80，不要集中打 70-75"，但实际仍集中在 62-78。LLM 对"不要集中"的指令不敏感。

**措施**：
1. **每维分档锚点更激进**：3 档（0-10 / 12-21 / 22-35），中间档区间窄，逼 LLM 选边——要么"有但一般"（12-21），要么"强"（22-35），要么"没有"（0-10）
2. **规则回退去掉"中性基线"**：当前 `_rule_dims` 对通用维度给满分 50% 基线，导致无 LLM 时所有内容都 60+。改为基线 30%（满分 × 0.3），关键词命中才加成——让规则回退也能产出低于 60 的分数
3. **few-shot 反例注入**：在 prompt 里给 1-2 个"这条内容看起来还行但实际只值 55 分"的例子，打破 LLM 的"看起来还行→70 分"惯性

## 四、分数分级语义（对用户的预览价值）

| 分数段 | 语义 | 当前问题 |
|---|---|---|
| 85+ | 必读/罕见强证据 | 当前无（最高 82，且是非意式内容） |
| 70-84 | 日报主内容 | 当前 22 条，但混入非意式内容 |
| 60-69 | 补充价值 | 当前 11 条，和咖啡渣笔记本混在一起 |
| <60 | 不发布 | min_score 拦截 |

**建议**：分数 badge 对用户有意义的前提是"分数可信"。当前 62 分混着优质调参个案和咖啡渣笔记本，badge 反而误导。改革后分数应能区分：优质意式内容 75-90，一般内容 60-70，无关内容被初筛/relevance 拒。

**可选**：60-69 分的条目在前端不展示分数 badge，只展示 why_read——避免"低分 badge 让用户觉得不值得读"的反效果。

| 优先级 | 改革 | 理由 |
|---|---|---|
| **P0** | 改革 1（初筛硬门强化）+ 改革 2（relevance 否决） | 解决"无关内容拿高分"——这是评分失效的首要原因 |

## 七、与上一轮方案的关键差异

| 维度 | 上一轮（6 类型 × 6 维） | 本轮（3-4 维 + 否决） |

| 规则回退基线 | 满分 50% | 满分 30%（让规则回退也能产出 <60） |
| 初筛 | LLM 优先，词表仅规则回退用 | LLM 返回前强制过词表，覆盖 LLM 放行 |

## 八、待用户确认的决策点

1. **relevance 否决阈值**：50% 是否合适？太高会误杀"意式占一部分"的内容，太低兜不住无关内容
2. **是否保留 evergreen 维度**：我建议全去掉（LLM 评不准，且日报定位是"今日资讯"非"长期参考"），但如果你认为"长期参考价值"对读者预览有意义，可保留在某类型的低权重位
3. **60-69 分是否展示分数 badge**：当前混入低质内容，badge 误导；改革后是否可信到可以展示
4. **是否跑 --rescore 重评旧 44 条**：新机制下旧内容分数会变化（鸟类研究会被拒，冷冻豆调参会升到 85+），是否接受这种变化

## 九、实施与验证结果（2026-08-06 落地）

### 9.1 代码改动落地

| 文件 | 改动 |
| --- | --- |
| `src/score.py` | `CONTENT_TYPE_DIM_PROFILES`（6 类型独立维度集）+ `dim_keys/dim_max/dim_profile` 公共函数 + `_rule_dims` 按类型维度逐维打分（基线 30%）+ `_dim_rubric` 分发 6 段独立 rubric + `_call_llm_meta` 动态生成 scores 键提示 + `_relevance_vetoed` 一票否决 + `_hard_reject_check` 初筛硬拒 + `_is_espresso_research` 意式研究例外 |
| `src/pipeline.py` | `_d` 日志按 content_type 动态取维度键 |
| `src/quality_report.py` | `content_type_scores` 聚合 + `by_content_type` 统计 + 「按内容类型分布」表格 |
| `scripts/rescore.py` | 新增：重评旧内容的工具脚本，支持 LLM 精评/规则回退两种模式 |

### 9.2 实施中修复的 bug

1. **`_dim_rubric` KeyError**：原用 dict 字面量，Python 创建 dict 时会求值所有分支的 f-string，导致每个分支都访问同一 profile 而其他 ctype 的维度键不存在 → KeyError。改为 if/elif 分支，每个分支只在 ctype 匹配时求值。

2. **健康话题误杀意式研究**：`_hard_reject_check` 命中"健康"关键词时无例外，导致「意大利研究：意式浓缩降低肝病风险」被误拒。修复：与 LLM 路径的 `_is_espresso_research` 对齐，研究主体是 espresso/moka pot 等意式饮品本身时放行；泛咖啡健康研究仍拒。

3. **1Zpresso 维修个案拒绝理由不准**：1Zpresso J-Ultra 是支持意式研磨度的手摇磨，属意式器具，但"轴承生锈维修"无调参价值。原逻辑因 `espresso_core=false` 兜底拒，理由写成"非意式核心"（不准确）。修复：
   - LLM 初筛 prompt 明确「磨豆机含支持意式研磨度的手摇磨（1Zpresso/Commandante 等），不区分手摇与电动，只看是否支持意式研磨度」
   - 新增拒绝形态第 8 条「维修/耐用性个案：单点故障/维修经历/售后吐槽，无调参价值——即使机型本身是意式器具也拒」
   - `espresso_core` 定义明确「支持意式研磨度的磨豆机（含手摇磨）属于意式器具」

### 9.4 验证结论

1. **改革 1（初筛硬门）生效**：15 条非意式/低质内容被初筛拦截，不再进入评分池
2. **改革 2（relevance 否决）生效**：1 条初筛漏放的内容被 relevance<50% 兜底拒
3. **改革 3+4（维度集重构）生效**：4 条优质意式实操内容升到 87-91 分，与低质内容拉开 30+ 分差距
4. **改革 5（对抗中庸）生效**：通过条目分数分布从 62-78 三峰扩展到 42-91，区分度显著提升
5. **意式研究例外生效**：意式浓缩降低肝病风险研究正确放行（53 分，未触发否决）；泛咖啡健康研究仍被拒
6. **维修个案拒绝形态生效**：1Zpresso 轴承生锈被正确拒，理由从"非意式核心"修正为"维修个案无调参价值"

### 9.5 已知限制

- **规则回退对中文内容识别力不足**：`RULE_DIM_KEYWORDS` 以英文关键词为主，对 LLM 处理过的中文摘要命中不足，导致规则回退分数偏低。LLM 精评开启时不影响。
- **content_type 修正依赖 LLM**：规则回退只能从 source name 反推 hint → content_type，Barista Hustle 实验内容会被误判为 news。LLM 精评可修正。
- **P2 few-shot 反例注入未实施**：改革 5 第 3 点（在 prompt 注入"看起来还行但只值 55 分"的反例）尚未落地，留作后续优化。

### 9.6 中英文管线分离说明（重要）

本项目已将英文源与中文源的抓取配置和评分维度表分离：

| 维度 | 英文流 | 中文流 |
| --- | --- | --- |
| 抓取配置 | `config.example.toml`（CI 每日跑） | `config.zh.toml`（本地按需跑，gitignore） |
| 评分维度表 | `CONTENT_TYPE_DIM_PROFILES` | `CONTENT_TYPE_DIM_PROFILES_ZH` |
| 来源 | RSS 图文源（Reddit/Barista Hustle/Scott Rao 等） | B站搜索 + 知乎 CLI + 豆瓣（RSSHub） |
| 语言分发 | `score.py` 按 `item['lang']` 选择维度表 | 同左 |

**本次 v2 重构（从实际出发）只优化了英文源的评分维度集**。中文维度表 `CONTENT_TYPE_DIM_PROFILES_ZH` 当前是英文表的拷贝（结构与行为完全一致），尚未按中文源的内容特点做差异化优化。

**中文源待优化的方向**（留待后续）：
- 中文源以视频（B站）和问答（知乎）为主，内容形态与英文 RSS 图文源差异大
- B站视频标题党/封面党严重，标题与摘要的信号可信度低，可能需要不同的初筛策略
- 知乎问答的"参数具体度"判断逻辑不同（问答帖 vs Reddit 的帖子）
- 可考虑为中文源设计独立的维度集（如增加"视频信息密度"维度替代"信息密度"）
- 中文源的 `min_score` 可能需要独立配置（`min_score_zh`）
